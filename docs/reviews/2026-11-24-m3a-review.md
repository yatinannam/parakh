## Final review

The final whole-branch review (`e3831f6..ad5e109`, Opus) found no safety, key or free-tier defects. It also rescored every live turn with the normaliser as it was during the runs and with the final one, and found no hidden recognition error.

It found two Important issues:
- **I-1.** For a planned barge-in that never happened (`agent_finished_first`), the judge payload said the caller cut in, and `interruption_handling` was required. The judge scored it 2. The payload now says the barge-in did not happen, and the score is null. The two barge-in runs were re-judged.
- **I-2.** `--resume` skipped completed runs marked `timing_unreliable`, although they exit 2. A pair now counts as done only when its exit code is 0.

The single fix wave (`09b2d49`, `3423e2e`) took both, plus:
- **Code fixes:**
  - The `rate_limited` relabel applies to timeout statuses only.
  - A Groq `json_validate_failed` 400 is retried.
  - `interruption_handling` defaults to null.
  - Duplicate scenario ids are rejected.
  - Payload newlines are flattened.
  - Filler handling covers हम्म with any number of m.
- **Normaliser gaps:** six merges (बच्चा/बचा, जगह/जागा and others) are recorded as known gaps.
- **Disclosure:** the as-run WER is stated next to the rescored one. Estimated tokens are no longer described as usage. Calibration is marked pending.
- **Wording:** "M3" now reads M3b where it means M3b.

The scoped re-review found every item addressed. Its one residual, a pair total written 263 instead of 269, was corrected by the controller (`e9de17f`).

## Rulings

### Carried from planning

These are in the plan's Global Constraints:
1. M3 is split into M3a and M3b. Recorded as D15.
2. The judge models are Groq `openai/gpt-oss-120b` in JSON object mode, with Gemini `gemini-flash-lite-latest` as fallback at an RPD of 20. Recorded as D16.
3. The judge runs by default. Recorded as D17.
4. Scenarios gain a `goal` field, and reports gain `scenario_goal`.
5. Resume skips completed pairs, and the comparison shows the newest report per pair.
6. An agent-reported 429 gives `rate_limited`.
7. Hypothesis joins the dev group.
8. The agent token figure was assumed until Task 9 measured it.

### Made during the run

In order, each with its cost if wrong:

1. **R1.** The pack's budget test checks request counts only, because Task 6's token check was expected to flag the pack. Cost: a narrower test.
2. **R2.** `parakh/judge/__init__.py` holds only a docstring, which avoids an import cycle. Cost: none.
3. **R3.** A turn counts as reached when its `latency_reason` is neither "turn not reached" nor "no data". "Nothing to judge" means no reached turn and no agent text. Cost: a mislabelled reached turn would be skipped.
4. **R4.** Event-metric helpers moved to `report/metrics.py` to keep `build.py` under the line budget. Cost: one more module.
5. **R5.** The final-h rule is limited to words of 4 or more letters, or words ending in "oh". On every word it merges कह/का and यह/या. Cost: a 3-letter word that ends in vowel plus h never matches its spelling without the h.
6. **R6.** English number words are looked up by loose key, which keeps normalising idempotent. Cost: an English word whose key equals a number word reads as a number.
7. **R7.** Rare merges are accepted: bara reads 12, चौड़ा reads 14, चाह reads 6, बाई equals bye, सादे equals साढ़े. 13 and 60 are known gaps. Cost: rare false matches.
8. **R8.** y drops only between unequal vowels, although the plan gave the reorder as its example, because spec 6.7 forbids merging distinct words. Cost: y between equal vowels never drops.
9. **R9.** नैन reads 9 and सेवन reads 7, as a side effect of the Devanagari English digit words. वन, टू and फोर are excluded. Cost: rare false number reads.
10. **R10.** Any unexpected judge exception becomes `judge_error`, so the judge never crashes a run. Cost: a judge bug shows as `judge_error` instead of a traceback.
11. **R11.** One measuring run instead of two; the pack batches supply the rest of the token figures. Cost: none.
12. **R12.** The 13 remaining scenarios ran as three foreground batches, joined with `parakh compare`, to stay under the 10-minute foreground limit and avoid memory reaping. Cost: three batch ids.
13. **R13.** The `agent_finished_first` payload was fixed although the plan specified its wording, because spec 6.7 says such a turn is not scored. Cost: two runs re-judged.
14. **R14.** Resume counts a pair as done only when its exit code is 0, although the plan and spec said "completed". Cost: a completed run that is timing-unreliable is re-run.
15. **R15.** The fix wave also took the final review's smaller code and docs items. Cost: a larger fix wave.
16. **R16.** The controller corrected the golden pair total (263 to 269) without a second fix wave. Cost: that correction had no fresh reviewer; it was checked by loading the YAML and running the docs tests.

## Deferred findings

- Add a README note that the judge sends agent reply text to Groq by default. That matters for agents other than the synthetic clinic agent.
