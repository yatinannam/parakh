Task 11 (real runs with the Groq key) was run by the controller and reviewed like the others. Range `ca8f125..b2a8705`. Final state:

Exit criterion (spec 10) met: all five presets, barge-in turns and stop latency, the comparison page, and the degrader tolerance tests (mu-law byte-identical to ffmpeg; SNR within 0.5 dB; loss rate within 1 %; same seed same bytes; aliasing at least 50 dB down; no energy above 4 kHz within 40 dB).

## Final review

The final whole-branch review (`6a81184..feb5f75`) found two Important issues and four Minors worth fixing in the same wave:

- **I-1** The barge-in audio-stop rule (end of the last loud audio before a 200 ms gap) scored non-yielding agents as yielded: replies pause 259 to 400 ms inside one reply. Replaying the clinic agent's live reply with injected onsets and no interruption frames, 38 of 62 onsets came back "yielded". Fixed in two steps: an audio stop now needs quiet of at least 800 ms (`d2210b1`), or quiet of at least 500 ms that lasts until the caller's speech end (`b2a8705`, after the scoped re-review measured 6.5 to 23 % false yields for short barge-in clips under the first fix, and 0 of 336 with the 500 ms floor). Recorded M2 numbers are unchanged (both stops came through the interruption frame).
- **I-2** Comparison charts showed partial-call WER and latency unmarked. Runs that did not complete now get muted bars labelled with their status, and the table has a "Turns reached" row (`294f834`, `b2a8705`).
- **M-1 to M-4** `SNR n/a` without "dB"; the comparison path printed only when it was written; the interrupted partial report keeps the seed and degradation; `parakh degrade` no longer amplifies near-silent input and names an empty clip (`7fa5ee1`).

## Rulings

Rulings carried from planning (in the plan's Global Constraints): `phone_lossy` adds loss without noise and `bad_line` uses pink noise; SNR is set and measured at the mixing point before the telephone stage; the noise level is set once per call; one repeatable `--preset` (plus `all`) replaces `--presets`; user-supplied noise files and presets go to the backlog.

Rulings made during the run, in order, each with its cost if wrong:

1. Task 11 runs inline by the controller (it needs the Groq key and the stop-on-402/429 rule). Cost: one task without a fresh implementer.
2. Spec refinements recorded by T12: silent frames do not queue behind a backlog (6.4), the barge-in turn latency rule (6.7), observed request rates in the estimate (6.8). Cost: report numbers differ from M1 semantics for agents that stream silence during bursts.
3. Models: implementers and task reviewers on Sonnet, the final review on Opus. Cost: more fix rounds from a weaker implementer.
4. Subagent commits keep their own Co-Authored-By trailer. Cost: trailers differ between commits.
5. `run.py` split at Task 3's fix round into `report/build.py` (superseding a split planned for Task 7). Cost: none.
6. The mu-law SQNR test uses a 997 Hz tone at zero phase. Cost: none.
7. The band-limit timing test gains a trailing gap and an exact zero-lag test (the plan's test layout was the defect). Cost: none.
8. `parakh degrade` prints `snr n/a` without "dB". Cost: none.
9. `parakh degrade` scales noise to the clip's own slice; calls keep call-level scaling. Cost: none.
10. The barge-in onset test allows one extra 20 ms tick. Cost: a 20 ms late barge-in passes that test.
11. The clinic agent speaks with `hi-IN-SwaraNeural`, because `en-IN-NeerjaNeural` is silent on Devanagari. Cost: the agent and the booking caller share a voice.
12. Batch runs pause 3 s. Cost: 3 s per run.
13. Both Hinglish scenarios allow 15 s for a reply. Cost: a hung agent times out 7 s later.
14. Batch 2 ran `clean` and `phone`, not `phone_noisy` (the agent never greets under babble). Cost: no barge-in data under noise.
15. The 3 s gap stays although it does not remove all carry-over; a per-call VAD and STT reset in the agent goes on the backlog (EC-84). Cost: a run right after `phone_noisy` can carry a fragment of it.
16. I-1 is a plan and spec defect; an audio stop needs 800 ms of quiet or quiet until the caller's speech end. Cost: an agent pausing over 800 ms mid-reply counts as yielded.
17. M-4 entered the fix wave (Review Focus 5). Cost: none.
18. The re-reviewer's measured 500 ms floor on the speech-end clause applied as a post-review follow-up, checked by its tests, the full suite and the controller rather than a second fresh review. Cost: the follow-up had no fresh reviewer; an agent that replies within 500 ms of yielding across the caller's speech end scores `did_not_yield`.

## Deferred findings

Fix at the start of M3:
- Load and validate every scenario in a batch before the first call; optionally pre-build all clips and the babble (a late pre-call error aborts the rest of a batch).
- Reset the clinic agent's VAD and STT state per call (EC-84); the 3 s batch gap is a workaround.
- `parakh compare` default `--out` overwrites the first batch's page when joining batches; default to the common parent.
- Print each run's summary as it finishes, not only at the end of a batch.
- `os.path.relpath` raises across Windows drives in `parakh compare`; fall back to `as_uri()`.
- An OSError writing the comparison after a finished run aborts the rest of the batch.
- The interrupted report raises KeyError on a malformed event inside a suppress, writing no report; fall back to the minimal report.
- Degraded turns use `round()` for their length while clean uses the resampler's ceiling (one frame at most, for unaligned clips).
- `test_lossy_preset_logs_lost_frames` never asserts a True flag; bed loss is never exercised.
- `parakh degrade` exit-2 paths untested (unsupported rates, non-mono WAV, missing file, FfmpegMissing), plus non-16 kHz input, all-empty babble and seed variation.
- Entering AGENT_SPEAKING from CALLER_SPEAKING takes the old loud run's onset, so a second barge-in against a non-yielding agent can fire at once.

Later:
- Recorder: run joining copies the frame list per frame; `caller_frame` appends before `event()`; `caller_lead` takes no rate.
- Ctrl+C during TTS writes a fallback into a run dir the CLI never printed; `test_git_sha_none_on_timeout` depends on `.git`; no interrupt test raises `CancelledError`; an unused `_run_dir`.
- `telephone()` double-counts a sample both clipped and saturated; `band_limit` gives an opaque error at 6800 Hz or below.
- The wheel test only proves the source file exists; the SNR test scales and measures with the same function; the clean path is chosen by name; presets are validated at import without a cache; small naming and test-import nits in `seeds.py`, presets tests and `__all__`.
- `babble.py` imports a private helper and has a near-dead check; function-local imports in `test_cli.py`; `make_engine()` built without babble.
- The 10 s bed loops without smoothing its seam; `test_cli_run` asserts only "lost " in the HTML.
- Fake agent: its yield task and speak loop race on one deadline; the yields test never asserts the paced reply went silent; no unit test for a barge-in blocked by `max_turns`.
- `build.py` wraps stops in `TurnLatency` objects to reuse `latency_stats`; no HTML test for `agent_finished_first` or a multi-entry false barge-in list; a comment on the play-time versus arrival-time search start.
- Comparison: grouping by scenario id merges two files with the same id; the noise note prints for clean-only budgets; hrefs are not URL-encoded; `compare.py` relies on `html.py` to register filters; the chart scale includes partial runs.
- `on_batch` fires before any run; the CLI's pre-call-error branches are untested.
- Docs: the spec's EC-27 row wording about silent frames; the README exit table's "the comparison" needs "for a batch"; the README barge-in bullet rests on one run per preset; the RTVI repeats docstring's "They"; the banner test has no subprocess timeout.

Closed during review: `Mapped.interruption` (consumed in T2); 11025 and 22050 Hz frame sizes; `FakeBehaviour.user_started` (used in T9); "SNR n/a dB" (M-1); the comparison path for a batch with no page (M-2); CRLF in a working copy (git normalises line endings).
