# M1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `parakh run scenarios/hinglish/clinic-book-hinglish-01.yaml --preset clean` against `agents/clinic_agent` writes `report.json` and `report.html` with per-turn latency and strict and loose WER (spec section 10, M1).

**Architecture:** A scenario YAML is loaded and validated, its caller turns are synthesised with edge-tts and cached, and the call driver streams them in real-time 20 ms frames to the agent over a Pipecat protobuf WebSocket while a turn-taking state machine and a virtual playback clock decide when the caller speaks. Every frame is recorded with monotonic timestamps; after the call, latency is scored from the recorded events and WER from the agent's own RTVI transcript through a script-tolerant normaliser, and a JSON plus self-contained HTML report is written. The test agent is a Pipecat 1.16 bot (Silero VAD, Groq Whisper, Groq LLM, edge-tts) served on the same protocol.

**Tech Stack:** Python 3.11, uv, pydantic v2, Typer, numpy, scipy, edge-tts (LGPL, unmodified dependency), ffmpeg, websockets, pipecat-ai 1.16.0 (BSD-2), jiwer, indic-transliteration (MIT), Jinja2, psutil, pytest, pytest-asyncio.

**Spec:** `docs/superpowers/specs/2026-11-15-parakh-design.md` (sections 6.1, 6.2, 6.4, 6.5, 6.7, 6.9, 6.10, 7, 8, 10 and the M1 rows of 11).

## Global Constraints

- Free only, no card. Synthetic data only to remote APIs; scenario text is synthetic, so edge-tts and Groq receive only synthetic content.
- No Calibrate code (CC-BY-SA). No code copied from Pipecat or `pipecat.evals` either; use `pipecat-ai` only as a dependency.
- `pipecat-ai==1.16.0` exactly. Core Parakh depends on `pipecat-ai==1.16.0` (no extras) only for `pipecat.frames.protobufs.frames_pb2`. The agent uses the uv dependency group `agent` with `pipecat-ai[websocket,silero,groq]==1.16.0`.
- edge-tts is used unmodified as a dependency, never vendored (EC-62).
- `pathlib` everywhere; run ids are 8 hex characters (`secrets.token_hex(4)`); every test that touches paths uses a directory whose name contains a space (EC-07).
- Durations use `time.perf_counter_ns()` / `time.monotonic_ns()` only; wall-clock time is a label (EC-39).
- Caller audio is 16 kHz mono signed 16-bit PCM; 20 ms frames (320 samples); the agent's input rate is configurable (`--agent-rate`, default 16000) and every sent frame carries `sample_rate` (EC-21).
- "Agent speaking" threshold: -45 dBFS (EC-27). End-of-turn silence: 800 ms (EC-36). Caller-first line silence: 1000 ms (EC-35). Timing unreliable: p99 send jitter > 30 ms (EC-02). CPU warning above 85 % (EC-05).
- Exit codes: 0 completed; 1 the agent failed the call (`agent_hung_up_early` in M1); 2 infrastructure (`turn_timeout`, `call_timeout`, `agent_disconnected`, `agent_unreachable`, `protocol_error`, `timing_unreliable`, ffmpeg missing).
- Unit and integration tests need no network and no keys. Tests that need ffmpeg run in CI (Task 15 installs it); they are not skipped.
- No emoji anywhere. Conventional Commits. Push to `main` after each task.
- Decision D14 (recorded in Task 16): Parakh keeps its own call driver. `pipecat.evals` (new in Pipecat 1.16) needs the bot to run Pipecat's eval transport and serializer, measures pass/fail latency budgets, and has no telephone degradation or script-tolerant WER; it complements Parakh.
- Ruling carried from planning: Parakh makes no LLM or STT API calls of its own in M1 (the agent does). So EC-10's budget estimate ships in M1, while the token bucket, daily counter and 429 backoff (EC-10, EC-11) move to M3, when the judge makes Parakh's first LLM calls. `remote_call()` (EC-13) ships now and guards edge-tts. Task 16 updates the register.
- Ruling carried from planning: spec 6.5 says the frozen scenario clock reaches the agent through a session-start message and the HMS. In M1 the agent reads the same clock from its own `config.yaml` (equal to the scenario's); the session-start message arrives with the HMS in M4, where the clock first changes outcomes.
- Ruling carried from planning: spec 6.7 step 4 says "drop nasal marks"; a feasibility check showed `मैं` can then never match `main`. Anusvara and chandrabindu become `n` (`m` before p, b, m), recorded as a spec refinement in Task 16.

### Task 6: Turn-taking state machine

**Files:**
- Create: `src/parakh/caller/turns.py`
- Test: `tests/unit/test_turns.py`

**Interfaces:**

### Task 10: Script-tolerant normaliser

**Files:**
- Create: `src/parakh/score/normalize.py`, `tests/golden/normalizer_pairs.yaml`
- Test: `tests/unit/test_normalize.py`

**Interfaces:**
- Produces: `@dataclass(frozen=True) Normalized(tokens: list[str], script_unsupported: bool)`; `normalize(text: str) -> Normalized`; `strict_tokens(text: str) -> list[str]` (NFC, lowercase, punctuation including danda and double danda replaced by spaces, split); `tokens_equal(a: str, b: str) -> bool`; `VARIANTS: dict[str, str]`.

The rule order below passed every golden pair in a planning check; keep it.

1. NFC. Detect Perso-Arabic (U+0600 to U+06FF) and set `script_unsupported`.
2. Each Devanagari run (U+0900 to U+097F), word by word: map `ऑ` to `ओ` and `ॉ` to `ो` (ITRANS leaves candra o untouched); transliterate with `indic_transliteration.sanscript` from `DEVANAGARI` to `ITRANS`; if the result is longer than 2 characters and ends in a lowercase `a` after a non-vowel, drop that inherent schwa (a long vowel is `A` and is kept); anusvara `M` before p, b or m becomes `m`; remaining `M` and `.N` become `n`; remove `.`.
3. Lowercase; every character outside `[a-z0-9]` becomes a space; split.
4. Numbers, on these raw tokens: English `zero` to `nineteen`, the tens `twenty` to `ninety` with an optional following unit, `hundred` (100), `double X` and `triple X` for a single digit X; Hindi 0 to 10 in common spellings (`shunya ek do teen tin char chaar paanch panch chhe che chhah saat sat aath ath nau das`). Then adjacent digit tokens are concatenated (phone numbers, `98450 12345`).
5. Loose key for each non-digit token, in order: `c` not followed by `h` becomes `k`; `ph` to `f`, `w` to `v`, `q` to `k`, `z` to `j`; a final `ov` becomes `o`; `ee` to `i`, `oo` to `u`; runs of a repeated letter collapse to one; a `y` between two vowels is removed; then `VARIANTS = {"nahin": "nahi", "nai": "nahi", "men": "mein", "me": "mein", "rav": "rao"}`. `main` and `mein` stay distinct.
6. `tokens_equal`: equal strings; or, when neither is all digits, equal consonant skeletons (vowels and `y` removed, repeats collapsed) of length at least 3 with key lengths differing by at most 2.
